# 项目设计：自然语言空间分析助手

这是后续实现的目标设计，当前还没有 GIS 查询工具、模型接入或 CLI。

## 第一版解决什么问题

给定一个 GeoJSON 点数据集，用户提供中心点、类别和半径，程序返回范围内的地点、距离与结果文件。
自然语言中的条件由模型解析，距离和空间筛选由 GIS 代码计算。

第一版使用明确的经纬度和本地教学数据。地点名称转坐标、在线真实 POI、路径导航和地图网页可在基本流程完成后增加。

示例问题：“查询经度 121.4700、纬度 31.2300 周围 1 公里内的医院。”
模型需要把 1 公里转换为 1000 米，并生成类似以下参数：

```json
{
  "longitude": 121.4700,
  "latitude": 31.2300,
  "radius_m": 1000,
  "category": "hospital"
}
```

## 重要概念

- GIS：处理带有位置的数据，包括读取、查询、空间计算和结果表达。
- 大模型：理解语言，并根据工具说明生成调用请求。
- 工具：普通程序函数，有明确的输入、输出和校验规则。
- Agent：围绕任务运行模型与工具的执行流程。本项目第一版只有一个 Agent，不需要多个 Agent。
- GeoJSON：用 JSON 文本表示点、线、面等地理要素的开放格式。

## 一次查询的执行顺序

```text
用户问题
  ↓
模型生成工具名与参数
  ↓
程序检查工具名、参数类型、范围与调用次数
  ↓
search_nearby 读取数据，按类别筛选，计算测地线距离
  ↓
返回原始要素 ID、名称、距离、单位与数据来源
  ↓
模型依据工具结果组织回答，程序保存 GeoJSON 结果
```

模型不能通过文字自行确定距离。应用只执行已注册工具；第一版不提供任意 Python 代码或 Shell 执行工具。

## 工具约定（第 3 阶段实现）

`search_nearby(longitude, latitude, radius_m, category)`：

| 输入 | 约定 |
| --- | --- |
| `longitude` | 有限数值，范围 -180 到 180 |
| `latitude` | 有限数值，范围 -90 到 90 |
| `radius_m` | 有限数值，第一版要求大于 0 且不超过 100000 米 |
| `category` | 数据集支持的类别，第一版为 `hospital` 或 `park` |

使用 WGS 84 椭球测地线距离。筛选条件为 `distance_m <= radius_m`，按距离升序排列，同距离按 ID 排序。
先用完整精度筛选和排序，展示时再四舍五入，避免改变边界行为。

输出包括查询条件、数据来源、`count` 和 `results`。每条结果保存原要素 ID、名称、类别、坐标和 `distance_m`。
无匹配时返回 `count: 0` 与空列表。错误参数不调用计算函数，而是返回可理解的错误信息。

保存为 GeoJSON 时，将 `distance_m` 写入结果要素的 `properties`，保留原点几何。不要给生成的结果编造真实数据来源。

## 技术选择与理由

| 技术 | 何时引入 | 用途 |
| --- | --- | --- |
| Python 标准库 | 第一课 | 文件、JSON、循环、函数与入门检查 |
| pyproj | 第 2 阶段 | 正确计算以米为单位的测地线距离 |
| Shapely / GeoPandas | 空间分析扩展 | 几何关系、矢量数据与投影；按实际需要引入 |
| 模型服务官方 SDK | 第 4 阶段 | 真实模型请求与工具调用 |
| argparse、项目打包配置 | 第 5 阶段 | CLI 与可安装命令 |
| GitHub Actions | 第 6 阶段 | 在提交与 PR 上运行验证 |

先用直接的函数和消息循环理解原理。需要复杂状态、分支或恢复能力时，再考虑 Agent 框架。
当前不需要数据库、Docker 或前端框架。

## 将来的源码布局

```text
src/gis_agent/
├── data.py          # 读取和校验地理数据
├── spatial.py       # 距离与空间查询
├── tools.py         # 工具参数、注册与结果序列化
├── agent.py         # 模型与工具的消息循环
└── cli.py           # 处理命令行输入并展示、导出结果
tests/               # GIS 与工具执行流程的行为检查
```

## 什么说明它已经完成

工具可以在不接模型时独立验证；接入模型后可以观察到真实调用记录；最终回答能逐项对应工具结果；新环境能按 README 重现。
仅根据关键词返回一段固定回答，不能证明空间分析或 Agent 已经实现。
