# 课程路线：从零到可开源项目

按完成情况推进，不按天数赶进度。每阶段都要能运行、能解释、能独立修改一个条件。
本次已经准备环境与第一课材料，其余阶段是开发计划，尚未实现。

## 0. 理解工具与工作目录

- 学习：GitHub 仓库与 Codespaces 的区别，终端、路径、文件、Python 解释器、虚拟环境、Git 仓库与分支。
- 动手：先按 [第 0 步](00-github-codespaces.md) 在自己的 GitHub 创建学习分支与 Codespaces，导入材料，再进入项目目录、激活环境并运行示例。
- 完成标准：能解释 `cd`、`python`、`git status` 各做什么；知道代码文件保存在哪里。

## 1. 用 Python 读懂 GeoJSON

- 学习：变量、字符串、字典、列表、循环、条件、函数、返回值。
- 动手：读取 3 个教学点；自己实现按类别筛选的函数。
- 完成标准：第一课的 6 项行为检查通过；能把类别从 `hospital` 改成 `park` 并解释变化。
- 入口：[第一课](01-first-lesson.md)。

## 2. 做出真正的 GIS 距离查询

- 学习：经度、纬度、WGS 84、CRS（坐标参考系统），以及“度”和“米”的区别。
- 新工具：在虚拟环境中安装 `pyproj`；用 `pyproj.Geod` 计算椭球面测地线距离，返回米。
- 动手：先写 `distance_m(lon1, lat1, lon2, lat2)`，再写“按类别 + 半径”筛选和距离排序。
- 完成标准：同一点距离为 0；已知参考点对与独立参考值在合理误差内一致；半径边界、空结果和排序均正确。
- 数据约定：查询中心 `[121.4700, 31.2300]`，半径 1000 米。根据教学数据，医院甲应在结果内，医院乙应在结果外；精确距离由代码计算。
- 输出：结构化结果，包括地点 ID、名称和 `distance_m`，不是只有一句话。

扩展练习：学会 Shapely 的点与多边形关系后，增加区域筛选。做缓冲区时再学习合适的米制投影；不要对经纬度直接调用 `buffer(1000)`。

## 3. 把 GIS 函数封装成可靠的工具

- 学习：函数输入输出约定、JSON、参数校验、异常与可重复检查。
- 动手：定义 `search_nearby`，接受经纬度、半径和类别，返回可序列化 JSON。
- 完成标准：经纬度越界、负半径、不支持的类别得到明确错误；空查询返回空列表；每条结果可追溯到原始要素。
- 先直接用 Python 调用工具，确认计算可靠，再接 Agent。

## 4. 接入大模型的工具调用

- 学习：模型、提示词、工具定义、工具调用、工具结果、多轮消息和结束条件。
- 新工具：选择支持工具调用的模型服务，使用该服务的官方 Python SDK。接入前再配置相应 API 域名与密钥。
- 动手：把工具的名字、用途和参数结构提供给模型；接收工具调用；程序校验参数并执行工具；把结果回传给模型生成回答。
- 完成标准：自然语言查询触发真实工具调用，回答中的地点与距离都来自工具结果；信息不足时请求补充；未知工具和超出步数的循环得到处理。
- 没有模型密钥时，可以用固定工具调用消息验证执行流程；这种回放只是测试替身，不能作为 Agent 已完成的证据。

## 5. 形成可使用的命令行程序

- 学习：命令行参数、模块组织、结果文件、配置与错误提示。
- 动手：将程序整理为 `src/gis_agent/` 包，添加 CLI（命令行界面），支持自然语言提问和直接参数查询，导出 GeoJSON。
- 目标命令形态：`gis-agent ask "查询经度121.4700、纬度31.2300周围1公里内的医院"`。该命令目前尚不可用。
- 完成标准：从新终端按 README 能启动；输出说明单位和教学数据来源；无匹配、错误参数、服务不可用时行为明确。
- 可选扩展：地图显示、FastAPI 服务、真实开放数据、地点名称转坐标。先完成 CLI 的完整流程，再选择扩展。

## 6. 检查完整流程并发布到 GitHub

- 学习：有意义的测试、依赖版本、Git 提交、远程仓库同步、PR（合并请求）、开源许可证与版本发布。
- 动手：记录并固定实际验证过的依赖版本；添加自动检查；补齐安装与使用文档；从干净环境重现安装与运行；发布 `v0.1.0`。
- 完成标准：别人只凭 README 就能运行；GIS 关键计算和 Agent 工具执行都有检查；真实模型调用至少验证一次，并记录模型和日期；密钥不入库。
- 入口：[GitHub 发布指南](github-publishing.md)。

## 最终验收

1. 一条自然语言查询完成“识别条件 → 调用 GIS 工具 → 展示结果 → 导出文件”。
2. 回答中的数据与工具结果一致，距离单位正确，使用的数据来源清楚。
3. 空结果、缺少坐标、错误参数、模型调用失败都有清晰的处理方式。
4. 测地线计算、筛选边界、工具参数校验、工具调用流程通过检查。
5. GitHub 仓库具备源码、示例数据、README、许可证、依赖声明与可复现的运行方式。
6. 你能不看教程，解释主要模块并独立增加一个小功能。

## 卡住时的处理顺序

先读错误的最后一行，记录运行命令和报错，再确认目录、虚拟环境和输入。向导师提供这些信息，以及你已经尝试过的方法。可以先要提示、再要局部示例；不需要一开始就看完整答案。
